创意树洞

记录还没落地、但已经想清楚边界的产品创意。不追热点，不写概念稿，每一份档案都要回答「为什么值得做」和「为什么先不做」。

为什么公开记录

创意留在自己的笔记里，最大的损失不是被人抄走，是永远停留在「感觉可行」的状态。写成档案必须补上三样东西：真实约束、可核对的数据、明确的放弃清单。补完这三样，一个念头要么变得可以做，要么当场被否掉——两种结果都比放着强。

至于被抄：创意本身最不值钱，判断才值钱，而判断藏在那些「不做」里。把档案公开发在自有站点上，还能留下一个清楚的公开时间戳。

树洞的意思是：这里只负责说清楚和存好，不承诺任何项目会立项、开发或上线。档案随认知更新，修订会标注日期。

这个栏目的四条记录原则

原则具体要求
观点先行开头一句话给判断，不做背景铺垫，不写「随着……的发展」
数据有出处数字标阿拉伯数字，注明来源、口径与核对日期；估算值显式标注，不把推测写成事实
写清不做什么放弃清单比功能清单更能定义一个产品，尤其是涉及隐私与平台规则的项目
风险算得清把「会不会出事」换成期望损失与收益的对照，给出可执行的止损线

补记：两个项目，卡在同一堵墙

项目一往里收数据，项目二往外发内容，方向相反，却跨同一道边界——别人 App 里的数据与操作，主权不在自己手上。2026 年 10 月 14 日豆包手机助手的拒绝清单，等于替这两个创意做了一次公开对照实验。

做实验的一方筹码齐全：Android INJECT_EVENTS 系统级注入权限（通常需手机厂商系统私钥签名）、2026 年 7 月完成的端侧生成式人工智能服务备案、带页面级声明与完整操作日志的 SAEP 协议，以及硬件大厂加模型大厂的商务资源；二代官方称端到端任务成功率超过 80%。公示期结束，换回的是 151 款起、随后更新至 155 款应用的书面拒绝，和愿意开放 MCP 标准接口的 3 款第三方应用。

它同时否掉了两条常被当作兜底的路：GUI 读屏模拟点击（收数据与代操作都指望它）在协议层被排除；「等平台开放标准接口」在可规划周期内不成立，头部应用逐家谈判以年计。也同时留下了一条始终开放的路——多家媒体明确，「拒绝接入」不影响应用正常下载、安装、手动使用，受限的只是智能体的自动读屏与模拟点击。

所以两份档案收敛到同一个解，不是巧合：把自动化留在自己这一侧（本地解析、本地适配），把跨应用的最后一步交还给人（主动导出、人工发布）。豆包二代三层避让里的「对高风险节点强制人工接管」，和项目二的三层方案是同一句话。

2026-11-05 补记。依据豆包手机助手官方公告及央广网（2026-10-16）、中国经济网（2026-10-15）、澎湃新闻、南方+、21 世纪经济报道、赛迪网报道整理；清单每周三更新，各媒体统计 151 / 153 / 155 / 166 款不等，差异来自统计时点与口径。

项目一、项目二于 2026-11-05 补入豆包手机事件实证章节；项目三于 2026-11-08 补入，按同一套证据标准先核对口径、再算成本；项目四同日补入，用四层准入与 5W1H 把三份档案重排成收款顺序，前三篇也各补一节互链。

项目一商业计划2026-11-05

私谱 BP：一个只给自己用的人脉系统，必须先砍掉「自动收集」

个人 IP 与人脉系统，要求绝对私密、仅限自用；人脉散落在名片、通讯录、平台粉丝、社交群聊，还要能撮合亲友或陌生供需。这份 BP 的核心判断是：私密性与跨平台自动收集在架构上互斥，唯一自洽解是本地优先、主动导入、本地归并，撮合只给建议、不代发信息。2026 年 10 月豆包手机被 150 余款应用书面拒绝代操作，为「跨平台自动取数」补上了上限证据。

档案含：三个硬矛盾、豆包手机事件实证与四层技术墙（接口 / 读屏 / 风控 / 规则）、逐条法条对照、五层技术架构、三层加密脱敏、身份归并策略、撮合边界、友商对照、商业模式、12 周 MVP、三条止损红线。

项目二可行性分析2026-11-05

一键分发是个伪命题：把「会不会被封号」换成一个能算的账

图文视频一键分析各平台特点改标题、一键分发。核对 2026 年各平台开放接口后的结论比「可能被封号」更硬：小红书、微信视频号等对普通第三方没有内容发布接口，「全平台一键」技术上就不成立；再加上 2025-09-01 施行的 AI 生成内容标识办法，正确做法是把最后一步交还给人。豆包手机握有系统级注入权限仍只拿到 3 个标准接口，是这条判断最直接的实测佐证。

档案含：平台开放度矩阵、豆包手机事件实证（三条路径判决与风控连坐）、官方 API 与模拟登录风险对照、风控行为指纹、AI 标识义务、平台标题信息架构差异、期望损失模型、三层产品形态、分期路线与止损线。

项目三可行性分析2026-11-08

「几十亿条料号」是个口径问题：开源元器件数据库该做的只有一层唯一性

元器件数据库年订阅几万块，是不是贵在数据量？核对 SiliconExpert 中英文官网、竞品与开源项目后结论相反：存储每月几美元，500 多名工程师的持续规范化与证据溯源才是大头。这份档案先纠正「几万家原厂」「几十亿型号」两个口径，再把成本拆成可复核的算式。

档案含：三个数字口径对照、10 亿+ 记录的构成拆解、市场三层与定价矩阵、成本量级估算、欧盟数据库权与 TDM 例外、四个开源项目现状、Component URL 标识层方案、最小数据模型与 Git 治理、12 周分期、四条放弃清单与三条止损线。

项目四总纲与推进重排2026-11-08

从「能不能做」到「谁先付钱」：准入围墙下的 5W1H 重排

三份档案把「能不能做」论证得很扎实，却没回答「谁会在什么情况下付第一笔钱」。这一篇补上四层准入限制——服务条款、CDN 机器人策略、平台诉讼与厂商内部管控——再用 5W1H 逐格重排，给出 90 天节奏与可触发的数值止损线。

档案含：四层准入的证据与解除方式、四条动机的纠偏与样本偏差、5W1H 六维对比表、90 天数值止损、断供演练与人机分工、6 条 FAQ。
