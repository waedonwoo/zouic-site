从「能不能做」到「谁先付钱」：准入围墙下的 5W1H 重排

创意树洞 · 项目四 · 总纲与推进重排 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026-11-08

核心观点：前三篇不是分析得不透彻，是问错了问题。五百多个文本块把「能不能做」论证得很扎实，却没有一篇回答初创最要命的那句——谁会在什么情况下付第一笔钱。更要紧的是，2026 年真正改写前提的不是模型能力，而是准入：从服务条款到网络基础设施，从平台诉讼到厂商内部管控，「能不能被访问」已经不是一个技术假设，而是一组随时会变的合同与商业条件。这份总纲补两件事：把准入风险写进设计前提；用 5W1H 把三个项目从「可行性」重排成「收款顺序」。

本篇不推翻前三份档案。风险尽调、法规对照、放弃清单仍然成立，只是在它们之上加一层「外部依赖随时可能断供」的约束，并把原本定性的止损线换成带数字、可触发的条件。

核对日期 2026-11-08。厂商公告、法院文书、学术论文与分析机构预测的口径逐条标注，推测不写成事实。文中所有阈值是本站为一人公司设定的经营止损线，属自定估算，不是行业基准。

一、新增的风险：不是一堵墙，是四层准入

「互联网巨头和大模型头部厂家以安全为名设防火墙」这个判断方向对，但只覆盖了一条动机。按 2026-11-08 能核到的公开材料，限制是分层的，每一层的解除方式完全不同。

层级公开证据与核对日期对一人公司的约束
合同层 · 模型服务条款2026-01-01 生效的 OpenAI 个人服务条款禁止自动或程序化提取数据与输出、禁止绕过速率限制和保护措施，并禁止用输出开发与 OpenAI 竞争的模型；Anthropic 商业条款与 Google Gemini API 附加条款有同类限制（中伦律师事务所 2026 条文梳理）。2026-04-22 美国参议院司法委员会书面证词把所谓「蒸馏攻击」明确归为 breach of terms of service，即合同违约，而非严格法律意义上的窃取。不训练模型不等于没有合同风险。只要工作流依赖批量调用、并把输出沉淀成自己的资产，就要逐条审服务条款、数据处理附录与企业订阅的特殊条款。
基础设施层 · CDN 与机器人策略Cloudflare 2025-07-01 起对新域名默认拒绝 AI 爬虫，从 opt-out 转为 opt-in；2025-09-24 发布 Content Signals Policy 并写入 380 万以上域名的托管 robots.txt；2026-07-01 把自动流量分为 Search / Agent / Training 三类并下放至免费档；官方公告明确 2026-09-15 起，带广告页面的新域名默认屏蔽 Training 与 Agent、放行 Search，混合用途爬虫按最严规则处理。「能被抓到」不再默认成立。Search、Agent、Training 要分别申请放行；llms.txt 与 Content Signals 都是声明与请求，不是通行证。
平台与司法层亚马逊 2025-11 起诉 Perplexity 的 Comet 代理购物，2026-03 加州地院发出初步禁令，2026-08-04 第九巡回上诉法院以「代理是工具不是人、进入平台的是用户本人」撤销禁令，同时明确不为智能体设立新制度、平台仍可通过服务条款限制访问；2026-09-21 亚马逊提交修订诉状，案件继续。Reddit 诉 Perplexity / SerpApi 一案 2026-07 大部分驳回动议被否。刑法层面的门槛变低了，合同层面的门槛没变。不要按「法院判我能进」做产品，要按「平台随时能改条款」做产品。
厂商内部与生态层2026 上半年媒体报道：Google 因安全考虑限制多数员工使用 Claude Code / Codex，并因算力配额限制供给 Meta 的 Gemini 调用量；微软取消多数 Claude Code 内部许可；Meta 限制在模型构建中使用竞品工具。腾讯 2026-09 公开阐述「大模型应用防火墙」「智能体安全沙箱」「逐项授权与操作留痕」「第三方技能供应链安全」。MCP 与技能生态既是新分发渠道，也是新的审查面。第三方 server 能否被调用，取决于宿主策略，不取决于协议是否标准。

先把「以安全为名」这句话校准一下：至少四条动机并存——算力配额（每次调用有真实边际成本）、数据边界（防内部机密外流）、资产保护（防蒸馏与研发流水线污染）、商业授权（Pay Per Crawl 演进到 Pay Per Use 与 x402，可对页面、数据集、API 甚至 MCP 工具计价）。把它们全归到安全，会误判成「自证合规就能过」；而配额和授权是结构性的，谈不下来，只能绕开或付费。

还有一层少有人算的样本偏差：ACM Web Conference 2026 论文（Steinacker-Olsztyn、Gosain、Dao）测到 60.0% 的优质新闻站至少拒绝一个 AI 爬虫，misinformation 站只有 9.1%，优质站平均点名 15.5 个 AI user agent；SIGIR 2026 对 11,500 条真实查询的研究发现，屏蔽 Google AI 爬虫的站显著更少被 AI Overviews 检索。也就是说，Agent 能读到的内容本来就是被筛过的偏样本。反过来，TollBit 2026-02 口径称 2025 年第四季度约 30% 的 AI bot 抓取未遵守明确的 robots.txt 许可（第三方监测，非平台自述）。「被允许」和「被引用」是两件事，都不能写进商业计划的默认前提。

落到设计上只有三条纪律：数据入口只走用户主动导出与权利清晰的授权源，不把抓取当主渠道；模型可替换，评测集与双供应商是标配；交付物必须可下载、可离线复核，不绑定某一个 Agent 或某一家平台。

二、5W1H：把三份档案逐格重排成收款顺序

5W1H 是老框架，价值不在新鲜，在于它强制逐格填实。用这个框架回看三篇，Who 和 When 两格基本是空的——写了「目标用户」却没写「谁签字付款」，写了「12 周 MVP」却没写「第几周收到第一笔钱」。下面每一格都只写能被证伪的内容。

维度项目一 · 私谱（关系实体）项目二 · 合规交付包与机器可读资产项目三 · resolve() 与证据链
What · 到底卖什么一次性的「关系梳理与引荐路径审计」交付，不是订阅 App；输出是一份可下载的引荐路径清单与依据。一份原稿生成 N 个带标识自检的合规交付包，加一份机器可读资产（原创统计块、结构化问答、llms.txt 条目），不是「一键发布到平台」。一次 resolve() 调用与带来源、版本、时间戳、置信度的证据链；「查无此料」是一等结果，不是再做一个数据库网站。
Why · 为什么是现在关系层挤满了讲「本地优先 / 记忆主权」的产品，绝对私密已是入场券；没人存的是「谁能引荐谁、凭什么、有没有被用过」。抽取与归并变便宜，但渠道与信任没有。准入收紧之后，「抓得到」贬值，「授权与自有」升值；AI 生成内容标识义务让显式声明与隐式元数据写入校验变成真痛点。本站 60 多篇三语长文与结构化数据就是第 0 个实验田。工业文档 AI 的瓶颈不在抽取，在解析与消解；「自信地匹配错」比「匹配不到」贵得多。每条断言留证，正好适应一个来源需要授权的世界。
Who · 谁付第一笔钱有引荐需求但不愿把关系上云的独立顾问、猎头、行业 BD。付款人即使用者，但需求低频、难以标准化，验证最慢。有稳定更新节奏的自媒体与小机构，本站自己是第 0 个客户；付款人是内容负责人，决策链最短。硬件小团队、独立采购顾问、二手算力卡残值评估方。付款人是工程或采购负责人，需对证据链签字，客单最高、验证链路最长。
When · 多久能验证90 天内只做自用工具，不投入商业化；若到时没有非熟人主动索取，永久降级。0–30 天在站内跑通，拿到发布率、误判率、被引用数三项真实数据。31–60 天先人工交付 100–500 行 BOM 消歧审计报告，按行收费；代码排在第二单之后。
Where · 在哪交付、流量从哪来只监听 127.0.0.1 的 MCP server，不进应用商店；能否被调用由宿主 Agent 决定，因此不做增长假设。自有域名 + 可下载的交付包文件 + 被 Agent 引用的机器可读条目；分发对象从人扩展到 Agent，但入口不押任何单一平台。MCP / 简单 HTTP API，起步是一份人工 PDF 报告；只接已授权数据源，不覆盖分销商价格与库存。
How · 怎么造、人机怎么分小模型做抽取、去重、实体候选合并；人做关系确认与引荐授权，绝不自动发消息。小模型做多解且错误可 containment 的改写与校验；登录、发布、合规声明永远留给人。小模型做抽取与候选匹配，单位换算单独做、属性允许显式空；人做最终消歧签字与争议仲裁。

最脆弱的一格是 Who。三个项目原来的止损线都是「做不到就停」这类抽象表述，没有付款人就无法证伪；把 Who 填实之后，排序自然变成「验证速度 × 现有资产 × 收款难度」：项目二最快，项目三有明确付费方但缺行业渠道，项目一最慢且赛道最挤。一人公司不该并行推三条线。

三、90 天节奏与可触发的数值止损

以下阈值是本站为一人公司设定的经营止损线（自定估算，非行业基准），每条都必须有可观测的触发条件，避免「再看看」式拖延。

  • 0–30 天 · 项目二优先：给 llms.txt 补原创统计条目、建一张 AI 引用监控表、把两份档案做成合规交付包。止损：若 30 天内机器可读条目在 3 个主流助手里 0 次被引用，且没有一位非熟人愿意为交付包付费，项目二降级为自用工具，不再投入产品化。
  • 31–60 天 · 项目三验证付费方：人工交付 2 份 100–500 行 BOM 消歧审计报告，按行收费。止损：若两份报告都拿不到复购或转介绍，或单行人审均耗时超过 3 分钟，停止自动化投入，保留报告模板作为服务页素材。
  • 61–90 天 · 收口：把重复步骤做成 resolve() 原型，只对已授权数据源开放；项目一维持自用 MCP，不立项。总止损：若 90 天内三条线合计付费收入低于 5,000 元，或没有任何一个非熟人客户，全部回退为内容与自用工具，不申请外部资源、不注册主体。

这里刻意不写估值、用户数与覆盖率。一人公司先验证现金流，再谈规模；Gartner 2026 年口径是仅约 17% 的组织真正部署了 AI Agent、超过 60% 计划两年内部署，同时预测到 2027 年底超过 40% 的 agentic AI 项目会因成本攀升、价值不清或风控不足被取消。这是分析机构预测而非既成事实，但三个取消理由恰好是一人公司最容易踩的坑。

四、断供演练：如果明天这三条路被关掉

准入风险只有翻译成具体动作才有用。对每个项目各问一次「明天断供怎么办」，答案必须能在一天内切换，不能是「再找一家」。

  • 模型 API 不可用或条款变更：评测集 + 至少两家可替换供应商 + 本地小模型兜底；每次输出记录 model / prompt 版本 / 时间戳，保证历史结论可重放。
  • 目标平台封禁自动化访问：项目二本来就只交付文件，不代登录、不代发；项目一、三的数据来自用户主动导出与授权源，不依赖抓取。
  • 上游数据源要求付费授权或发出停止函：项目三按来源粒度下线，不绕开；原档案里「宁可 1 万条可复核记录，不要 1 亿条来路不明的行」在按次计费时代更成立。
  • 四条纪律：可替换的模型、可授权的数据、可下载的输出、可审计的日志。任何一条不满足，就不把该环节写进对客户的承诺。
  • 交给 Agent：调研、竞品与法规核对、抽取去重、原型与测试、三语初稿、内容改写、客服首轮。
  • 留给人：定价、客户承诺、对外发布、合规声明、证据链签字、争议仲裁。Gartner 把「只有一个正确答案、错了有法律或财务后果」的场景明确划在 Agent 适用范围之外。
  • 成本口径别写反：a16z 的 LLMflation 观测是同等能力等级推理成本约每年降 10 倍，GPT-3 级（MMLU 42）从 2021-11 的每百万 token 约 60 美元降到 2024 年底约 0.06 美元；原文自述方法粗糙，且限定「能力固定」，不是旗舰模型降价。端侧小模型加廉价 API 的月推理费可以压到几十元级，真正的成本始终是人审与客户沟通。

总结

三个项目其实是同一件事：把不可验证的私有或专业知识，变成可验证的实体与可调用的接口。项目一是关系实体，项目三是物料实体，项目二是把这两类资产变成人和 Agent 都能引用的内容。共同底座意味着不该并行推三条线。

新增的准入风险不是让人收手，而是把「依赖外部恩准」的部分从计划里剔掉：不靠抓取、不靠自动发布、不靠单一模型厂商、不靠平台开放接口。剩下的部分——自有内容、人工可复核的判断、带来源的证据链——恰恰是围墙越多越值钱的部分。

一句话收口：可行性报告回答「能不能做」，5W1H 回答「谁先付钱」；把止损线写成数字，把准入写成设计约束，创意才从档案变成生意。

常见问题

巨头真的只是「以安全为名」设墙吗？

方向对，但不能单归因。至少四条动机并存：算力配额（每次调用都有真实边际成本）、数据边界（防内部机密外流）、资产保护（防蒸馏与研发流水线污染）、商业授权（从 Pay Per Crawl 到 Pay Per Use 与 x402 计价）。安全是公开理由之一，也是最容易通过自证合规缓解的一条；配额与授权是结构性的，谈不下来，只能绕开或付费。把四层全当成安全墙，会做错应对。

服务条款禁的是蒸馏，我又没训练模型，跟这三个项目有什么关系？

有关系，但触发的不是「竞品模型」那一条。OpenAI 2026-01-01 生效的个人服务条款同时禁止自动或程序化提取数据与输出、禁止绕过速率限制和保护措施；Anthropic、Google 的条款也各有类似限制。只要工作流依赖批量调用、并把输出沉淀成自己的长期资产，就要审服务条款、数据处理附录与企业订阅特殊条款。2026-04-22 美国参议院书面证词把蒸馏争议定性为合同违约，说明主战场是合同与访问控制，不是版权。

Cloudflare 默认拦截 Agent，那「面向 Agent 的内容资产」是不是白做？

恰恰相反，但做法要改。Cloudflare 2026-07-01 把自动流量分为 Search / Agent / Training，公告明确 2026-09-15 起带广告页面的新域名默认屏蔽 Training 与 Agent、放行 Search；这说明「被抓」不再是默认权利，授权、自有渠道和可下载交付物反而升值。要注意三点：三类要分别申请放行；Content Signals 与 llms.txt 是声明与请求而非通行证；被允许不等于被引用。另外别把站放在默认全拒的配置下还指望被引用。

为什么说 Who（谁付第一笔钱）比技术可行性更重要？

因为前三篇的止损线是「做不到就停」这类抽象表述，没有付款人就无法证伪。填上 Who 之后才能区分三种付款结构：项目二付款人是内容负责人、决策链最短且本站可作第 0 个客户；项目三付款人是工程或采购负责人、客单高但要为证据链签字；项目一付款人即使用者但需求低频。排序由此变成验证速度 × 现有资产 × 收款难度，而不是技术难度。

5W1H 这么基础的框架，用在这里有什么增量？

增量在强制逐格填实。用六个维度回看三篇，What 和 Why 写得很满，How 也细，但 Who 缺「谁签字付款」、When 缺「第几周收到第一笔钱」、Where 缺「入口是否被别人控制」。补齐这三格之后，三个原本并列的项目自动分出了先后，并且每条都能设一个可观测的触发条件。框架不产生洞见，它负责暴露空洞。

用 Agent 推进项目，最大的隐性成本是什么？

不是推理费，是人审与客户沟通。a16z 的 LLMflation 观测是同等能力等级推理成本约每年降 10 倍，且原文明确限定「能力固定」、自述方法粗糙；端侧小模型加廉价 API 的月推理费可以压到几十元级。Gartner 2026 年则预测到 2027 年底超过 40% 的 agentic AI 项目会因成本攀升、价值不清或风控不足被取消（预测，非既成事实）。三者里后两条都指向人：必须留评测集、每次输出记录 model 与 prompt 版本与时间戳、抽样人审和审计日志，定价与对外承诺不交给 Agent。
