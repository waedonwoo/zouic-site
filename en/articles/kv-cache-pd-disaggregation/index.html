In long-context inference the biggest cost is not compute, it is remembering the history

Compute industry notes · GeekWaedon @GeekWaedon

GeekWaedon @GeekWaedon · November 2026

On the same GPU, changing how KV Cache is managed can change the number of requests served several-fold. The most tangible performance gain in 2026 inference systems comes not from new silicon but from moving the job of 'remembering history' out of GPU memory.

First, the conflict between the two phases

LLM inference splits into prefill (compute the whole prompt once, compute-bound) and decode (generate token by token, memory-bandwidth-bound). Conventional deployment puts both on the same card, which is awkward: a long-prompt prefill stalls requests that are already generating, so TTFT and TPOT drag each other down, while every session's KV Cache occupies precious HBM — the longer the context and the higher the concurrency, the sooner memory runs out.

PD disaggregation sends the two request types to different nodes and passes intermediate state through a shared distributed KV Cache pool. It sounds like a scheduling tweak, but it actually turns memory capacity from a per-card constraint into a cluster-level resource pool: HBM, host DRAM, SSD and CXL memory pools form a hierarchy, with hot data kept close and cold data pushed down.

One open-source project made this route work

Mooncake (led by Moonshot AI's Kimi team and Tsinghua MADSys; best paper at FAST '25) is the most complete public implementation. Its official repository reports two classes of numbers:

40 GB is not an arbitrary figure: it is roughly the KV Cache of LLaMA3-70B at 128k context. In other words, whether long context is feasible, and how expensive it is, now depends mainly on how long it takes to move those 40 GB between nodes. For the first time, network and storage are leading terms in the inference latency equation.

Ecosystem convergence in 2026 matters more than any single benchmark

To judge whether a systems-engineering idea has really landed, look at how many mainstream frameworks changed code for it: Mooncake joined the PyTorch ecosystem in February 2026; vLLM and SGLang use it as the main backend for disaggregated prefill; LMDeploy, FastDeploy, llm-d and Dynamo have merged support; and in October 2026 TensorRT-LLM merged a native Mooncake Store connector in KVCMv2 for content-addressed cross-instance prefix reuse. PD disaggregation is no longer one model provider's private optimisation — it is one of the default options in the inference stack.

The memory-media layer is filling in too: in March 2026 the YuanNao KOS team contributed native support for single-tier CXL storage to Mooncake, and in September Sugon ParaStor became the first commercial distributed storage backend. CXL 3.1 is in volume production, and CXL 4.0 (released November 2025) raises the rate to 128 GT/s. Production-side figures disclosed by Tencent and others (vendor press releases, not third-party audits) claim KV Cache hit rates up to 90%, 6x long-text throughput and 30-40% lower GPU cost. Discount those numbers, but the direction is consistent.

Bottom line

Trading memory for compute is the most accurate summary of this architectural shift: rather than having every GPU recompute the same prefix, store the computed result in DRAM, SSD and RDMA networks and reuse it. Teams running their own inference service should reorder their priorities — look at KV hit rate and cross-node transfer bandwidth before deciding to add cards. Once 128k context is standard, the marginal return on another GPU may well be lower than that of a 400 Gbps network and a well-designed cache pool.

Frequently asked questions

What is PD disaggregation?

Prefill (compute-bound) and decode (memory-bandwidth-bound) run on different nodes, with intermediate state passed through a distributed KV Cache pool over RDMA. Long prompts no longer stall requests that are generating, and KV Cache stops monopolising a single card's HBM.

Why is KV Cache worth optimising separately?

It grows linearly with context length and concurrency and is the first resource long-context services exhaust. Keeping hot data in HBM, pushing cold data to DRAM/SSD/CXL pools, and reusing prefixes to avoid repeated prefill can raise throughput substantially.

Can it work without an RDMA network?

Yes, but with limited benefit. Mooncake's Transfer Engine reaches 190 GB/s over 8x400 Gbps RoCE, 2.4-4.6x faster than TCP, and the project explicitly recommends testing on a high-speed RDMA fabric.
