# 选型的正确顺序：先看场景，再看约束，最后看板卡

> 《开源硬件实战选型手册》 · 极客微栋 @GeekWaedon
> 原文：https://www.zouic.com/articles/handbook-ch1/

## 1.1 一个熟悉的剧本

你想做一个东西——比如能远程查看的温湿度计。你打开购物网站，搜索"开发板"，按销量排序，看到一块参数唬人的板子：主频几百兆、几十个 GPIO、还"赠送教程"。价格不贵，下单。三天后板子到了。然后你发现：教程是五年前的，配套的 IDE 装不上，搜报错信息只有英文论坛的三条陈年帖子。又过了一周，板子进了抽屉。问题不在你，也不全在卖家。问题在于选型的顺序反了。

## 1.2 错误顺序 vs 正确顺序

错误顺序（90% 新手的本能）：看参数 → 看价格 → 下单 → 再想要做什么。正确顺序：场景 → 约束 → 板卡。开发板不是快消品，它是一个生态系统的入口。你买的不只是一块 PCB，而是它背后的教程、库、社区和踩坑记录。参数表上的主频数字决定不了项目成败，生态才决定。

## 1.3 第一步：把场景说清楚

"我想做个智能设备"不是一个场景，是一个愿望。合格的场景描述要回答四个问题：做什么？给谁用？放在哪？跑多久？以远程温湿度计为例：采集温湿度并上报到手机可看的页面；自己用，放在家里；客厅有插座，但也想试试阳台；长期开着，最好几个月不用管。把这个模板填完，候选板卡其实已经砍掉了一大半。

## 1.4 第二步：三类典型约束

约束是把候选集从"几十块"收敛到"两三块"的筛子。

**约束一：联网需求。** 不联网 → 所有 MCU 板都在候选里；WiFi/蓝牙 → 乐鑫 ESP32 系列、Pico W、Nano ESP32；远距离低功耗 → LoRa（主力板 + 模块）；新协议尝鲜 → NearLink，但要接受生态早期。

**约束二：实时性要求。** 问自己：系统响应慢 0.1 秒，会出事故吗？会（电机控制、PID、平衡车）→ 需要硬实时，选 STM32 这类传统 MCU；不会（温湿度上报、人机交互）→ Linux 板也能用。一句话：人眼能容忍的延迟，MCU 一定够；电机不能容忍的延迟，Linux 一定不行。

**约束三：生态成熟度。** 中文教程多不多、外设有没有现成库、报错搜不搜得到。这就是推荐新手从 ESP32 或 STM32 起步的原因——不是它们最强，而是你卡住的每一步，都有人卡住过并且写下了答案。

次级约束（预算、功耗）放在这三条之后：30 块和 60 块的差价，远不如"能不能做出来"重要。

## 1.5 一次完整的推演

场景：家庭自用，客厅/阳台，长期运行 → 约束一（联网）：要 WiFi，砍掉所有不带无线的板子 → 约束二（实时性）：人眼看数据，慢半秒无所谓，不筛 → 约束三（生态）：新手第一个项目，要教程多，乐鑫系胜出 → 次级约束：预算敏感选 ESP32-C3（¥级），想顺便玩屏幕选 ESP32-S3（¥¥） → 结论：ESP32-S3-DevKitC 或 ESP32-C3-DevKitM。整个推演不到两分钟，但每一步都有依据。它不保证你选到参数最强的板子，它保证你选到能把项目做完的板子。

## 1.6 三个思维陷阱

**陷阱一：参数崇拜。** 参数过剩不会让你成功，生态贫瘠一定会让你失败。

**陷阱二：架构情怀。** 第一个项目就上 RISC-V Linux 板，你面对的是新架构、新系统、新项目三层陌生。一次只挑战一层。

**陷阱三：一步到位心态。** 没有全能板：带 WiFi 的不擅长硬实时，跑 Linux 的不省电。开发板是消耗品，不是传家宝。

## 1.7 本章检查清单

- 我写下四要素场景描述了吗？（做什么/给谁用/放哪里/跑多久）
- 联网需求明确了吗？（不联网/WiFi/远距离/新协议）
- 实时性要求判断了吗？（0.1 秒延迟会不会出事故）
- 搜过候选板的中文教程数量吗？（少于 10 篇就换）
- 要用的每个外设都确认有现成库吗？
- 预算约束放在最后考虑了吗？
- 我是在为"这个项目"选板，而不是为"以后所有项目"选板吗？
