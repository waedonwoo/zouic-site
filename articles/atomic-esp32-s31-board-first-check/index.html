S31板子今天上架，先查那个不报错的IDLE任务

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

任务不报错，却永远轮不上它跑。这是社区实测记录里最反常的一幕：听、看、推理、播放四件事一起跑，推理那一路既没变慢也没崩溃，在满负载下被调度器饿死，全程连一行报错都没有。11 月 23 日，正点原子发布 ATK-DNESP32S31 开发板，依托乐鑫 ESP32-S31 RISC-V 多核 AIoT SoC。截至 2026-11-24，厂商页面写满了参数和一句新品上市限时优惠，第三方价格和实测几乎空白。先把那句反常记在纸上：不报错，不等于在跑。

这块板给谁用：先把厂商写的和社区跑的分开

厂商页面写明，ESP32-S31 是双核 RISC-V，主频最高 320MHz，512KB RAM 可扩展 DDR PSRAM，带 Wi-Fi 6、BLE 5.4、经典蓝牙、Thread 1.4、Zigbee 3.0，还有 DVP 摄像头接口、RGB 屏接口、USB OTG、JPEG 编解码和千兆以太网，硬件安全引擎支持 AES、哈希、安全启动和 Flash 加密。这些是厂商页面写明的规格，照抄进你的准备表没问题。社区实测记录则是另一栏：什么值得买作者的《ESP32-S31 实战手记》第九篇记录了四路并发下的调度问题。两栏别混。厂商写的是能力清单，社区记的是一次实战，前者不是后者能跑通的保证。态度放这：单篇社区记录不是官方结论，照它排产之前先自己复现。

16MB 加 16MB，先弄明白装得下什么

厂商页面写明开发板标配 16MB Flash 加 16MB PSRAM。把这两个数做成能感觉的东西：16MB Flash 大约抵得上十几张 1.44MB 软盘，装的是程序和常量；16MB PSRAM 是运行时能摊开的桌面，摄像头帧缓冲和屏显数据都往这儿堆。厨房里灶台就那么大，Flash 是碗柜，PSRAM 是台面，台面不够，再好的厨师也摆不开四口锅。官方确认新增经典蓝牙，价格写的是「比 S3 贵一点」，但首发当日第三方价格和实测几乎为空，官方只给了「新品上市限时优惠」，没公布具体价格。准备阶段别替它填那个空。据社区报道，乐鑫已发布面向 ESP32-S31 的 Linux BSP 开发者预览版，要试的话先确认自己用的路子。

上电先走最小的那一步

上电别急着四路并发。第一步只点一块板：接电、看串口有没有输出、确认 Flash 和 PSRAM 都被识别。社区提示 S31 与 S3 的教程体系不兼容，代码、引脚、编译参数都不能照搬，所以别拿 S3 的工程直接烧，先建一个干净的最小工程。现阶段主要用 ESP-IDF，Arduino IDE 下暂时找不到这块板的支持，环境这一步就按 ESP-IDF 来。排队叫号是这里最贴切的比方：窗口只认你手里的号，S3 的号在 S31 的窗口不作数。先把一个有输出的工程跑起来，再往上加摄像头和屏。一次加一路，每加一路都看串口。

不报错的任务，要用 eTaskGetState 查它状态

社区实测记录里，四路并发时的优先级表是这样的：音频前端绑核优先级 6，屏显流约 5，推理只有 IDLE+3。三个数摆在一起就明白了，推理排在队伍最末，满负载时被调度器饿死，既没变慢也没崩溃，连报错都没有。作者建议用 eTaskGetState 查任务状态，区分「没看见」和「没在跑」。把这句话抄进你的记录表：每个任务记三列，优先级、状态、上一次运行时间。乐队指挥点名，点到谁谁出声；IDLE+3 就是那个永远排在点名册最后的名字，指挥没漏，是他始终没轮到。只看日志会以为一切正常，看状态才知道谁被饿着。

复核要自己复现一次，别信单篇记录

社区那篇实战手记写得细，可它终究是单篇社区记录，不是官方结论。复核的动作是自己复现：先把音频前端和屏显跑满，再启动推理任务，用 eTaskGetState 看它是不是又停在就绪态。复现出来，你手上才有自己的数据；复现不出来，也要记下当时的条件差异。复核表上与厂商页面并排留两栏，一栏写厂商写明的规格，一栏写你这板子实测的状态，两栏不互相替对方背书。立场再说一次：不报错不等于在跑，这条只能靠自己盯状态来验，不能靠日志里没有红色字样来安慰自己。

任务被饿死，先动优先级别动代码逻辑

一旦确认推理任务被饿死，先动的应是优先级安排，别急着改推理代码。社区记录给出的线索是音频前端 6、屏显约 5、推理 IDLE+3，那就先把推理的优先级往上挪，或者给绑核安排让出余地，再跑一次看 eTaskGetState 的结果。异常处理也分两类：一类是任务状态一直就绪却拿不到时间片，一类是任务真的算错了。前者调调度，后者查代码，别混着修。厨房里灶台不够，先调整哪口锅先开火，别急着把菜谱重写一遍。每改一次记录一次，改完立刻看状态，别凭感觉判断好了没有。

有些坑，现在就别往里跳

边界要写清楚，省得回头踩。S31 与 S3 的教程体系不兼容，代码、引脚、编译参数都不能照搬，手里只有 S3 资料的人先别开工。Arduino IDE 下暂时找不到这块板的支持，现阶段就用 ESP-IDF。官方没公布具体价格，也没有可信的第三方实测和跑分，到货时间同样没有公开口径，这三栏你填不了，就留空，别替厂商编一个数字进去。测评里的四路并发是单篇社区记录里的场景，不代表这块板的官方能力边界。把厂商写明的写在左边，把社区记载的写在右边，中间画条线，谁也别越过。

最后那道关，写在纸上再上电

回到开头那幕：任务不报错，却永远轮不上。截至 2026-11-24，厂商页面把规格和一句「新品上市限时优惠」摆了出来，价格和第三方实测仍是空的；社区那篇手记把 IDLE+3 的饿死现场记了下来，可它只是单篇记录。真正该带走的，是那个查状态的动作。厂商写的和社区跑的分栏记好，用 eTaskGetState 把「没在跑」从沉默里揪出来，复现时把自己的条件差异一并留下。等到某一次你看见推理那一路终于从 IDLE 被叫起来，屏幕上多出一行结果，那块板才算从货架上的参数变成你手里能调的设备。在那之前，它只是一块不报错也不干活的板子，安静得像没接通电源。

常见问题

ATK-DNESP32S31 和 S3 的教程能通用吗？

社区提示不能通用。S31 与 S3 的教程体系不兼容，代码、引脚、编译参数都不能照搬，手里只有 S3 工程的人先别直接烧录。现阶段主要用 ESP-IDF，Arduino IDE 下暂时找不到这块板的支持。据社区报道，乐鑫已发布面向 ESP32-S31 的 Linux BSP 开发者预览版，要用这条路径先确认预览版的适用范围。先建一个干净的最小工程，接通串口再往上加功能。

任务不报错，是不是就说明它在跑？

不是。社区实测记录显示，四路并发时音频前端绑核优先级 6、屏显流约 5、推理只有 IDLE+3，推理任务在满负载下被调度器饿死，既没变慢也没崩溃，全程没有一行报错。作者建议用 eTaskGetState 查任务状态，区分「没看见」和「没在跑」。这是单篇社区记录，不是官方结论，要自己复现并记下当时的条件差异。

价格和上市优惠该怎么看？

别替厂商填空白。厂商页面写明开发板标配 16MB Flash 加 16MB PSRAM，官方确认新增经典蓝牙，价格写的是「比 S3 贵一点」；首发当日第三方价格与实测几乎为空，官方只给了「新品上市限时优惠」，没有公布具体价格。同样没有公布的还有可信跑分和到货时间，这三栏留空即可，别把社区单篇记录里的场景当成官方能力边界。
