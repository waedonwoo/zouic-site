每瓦多出1.7倍token，自研芯片能替GPU吗

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

同样一度电，原来能跑 100 个 token，现在最多能跑 170 个。微软在 Ignite 2026（11 月 17 日）宣布，第二代自研 AI 推理加速器 Maia 200 投入规模化生产，并在数据中心运行最大前沿模型。官方博客里那句话带着明确限定：在 Microsoft Teams、Copilot、Cowork 的内置功能中，每瓦 token 处理量较「领先 GPU 基础设施」最高提升 1.7 倍。截至 2026-11-24，这组数字是厂商口径，对应的是自家业务里的特定负载。它能不能替掉 GPU，是另一个问题。

1.7 倍这个数字，先问跟谁比

把「最高 1.7 倍」读成一条通用成绩单，是最容易犯的错。官方口径写得很清楚：场景是 Teams、Copilot、Cowork 的内置功能，对照对象是「领先 GPU 基础设施」，而且用的是「最高」两个字。换个负载、换个对照基线，这个数字就不成立。微软 2026 年 10 月 28 日的财报电话会也提过同一个 1.7 倍，说的同样是 Teams 与 Copilot 的每瓦 token。我打个比方：自家厨房给一道招牌菜改了灶台，出餐速度提了七成，这说的是这道菜，谈不上整条街的餐厅。把厨房里的数字贴到商场成衣的价签上，比较的对象就错了。
限定词在，数字才有意义。

216GB 内存和 272MB 片上缓存，各管各的

规格表读起来像一份装修清单。Maia 200 采用台积电 3nm 工艺，配 FP4/FP8 张量核心，216GB HBM3e，272MB 片上 SRAM，单芯片 FP4 算力超过 10 petaFLOPS，最多可把 6144 颗加速器连成以太网集群。把 10 petaFLOPS 翻译成人话，就是每秒超过一千万亿次 FP4 运算；216GB 和 272MB 之间差了近八百倍，一个像仓库，一个像灶台边的料盒。这个分工决定了它能干什么：大内存负责把模型装下，片上 SRAM 负责让计算单元伸手就能拿到数据。好比量体裁衣，针脚走得密不密，取决于布料就在手边，还是要跑到库房去拿。

Scott Guthrie 在博客里写了哪几件事

披露人是微软 Cloud + AI 执行副总裁 Scott Guthrie。他在官方博客里写的是 Azure Maia 家族的部署进展：Maia 200 已投入规模化生产，在数据中心运行最大前沿模型，已在美国、欧洲、澳大利亚落地。这里要数清楚动作：博客披露、Ignite 现场宣布、财报电话会复述，三处出现的都是同一个 1.7 倍，场景限定也一致。把三处口径并排看，能看出微软在讲一个很收敛的故事：不讲通用排名，只讲自家业务里的能效。这种做法比扔出一个大数字更耐看，也更难被外推。
一个人写博客，三个人念同一行数字，说明这行数字是精心选过的。

先跑 Copilot，再谈对外卖不卖

部署顺序写得很具体：Maia 200 服务的是 Copilot 的生产负载，后续逐步支持 GitHub Copilot 与 Microsoft Foundry。先看它自己在跑什么，再看它对外卖什么，这两件事不能颠倒。公开信息里没有给出对外销售安排、定价或一般可用的采购入口。这像私家车和网约车的区别：自家厨房出餐快，是给自己员工吃的；要不要开到街上接单，是另一套证照和账本。把「已在生产环境运行」直接读成「可以下单采购」，等于把厨房的门锁当成店门。

自家厨房出餐快，不等于能开连锁店

所以这 1.7 倍更像一份能效样本，谈不上通用 GPU 的替代宣言。它证明的是：在一个足够固定的负载里，专用芯片能把每瓦 token 往上推一截。它证明不了的是：换到任意模型、任意框架、任意客户手上，还能不能保持这个数字。我把立场放在这里：把限定词擦掉再传播，是这类自研芯片消息最常见的失真方式。要不要替 GPU，得先回答三个问题：对照基线是什么、负载范围有多窄、模型迁移要付多少成本。三个问题没答完，「替不替」这个问法本身就太早。

6144 颗连起来，是集群而非货架

规格里还有一行容易被忽略：最多 6144 颗加速器通过以太网组成集群。换成日常说法，这是六千多张卡在同一张网络表里协同，考验的是互连和调度，而非单芯片的峰值。把这一行和 1.7 倍放在一起看，才能看清微软的思路：一边把单芯片的能效做上去，一边把规模铺开。可规模铺开需要机房、电力、网络，也需要客户愿意把负载搬过来。这些东西公告里没给数字，就不该替它补上。台积电 3nm 是制造工艺，FP4/FP8 是数据格式，两者都进不了采购合同里的交付条款。

2027 年的多吉瓦，和今天的现货是两条线

计划写得很远：微软称 2027 年 Azure Maia 系统会扩到多吉瓦级；Maia 300 计划 2027 年投产，采用台积电 N2P 加 chiplet，每瓦 token 再提升约 40%。约 40% 换算过来，是同样一度电从 100 个 token 走到 140 个。但这两句都还停在计划里，谈不上交付。多吉瓦是规模目标，Maia 300 的 N2P 与 chiplet 是下一代路线，40% 是目标增幅。把 2027 年的计划写进今天的采购决策，等于拿装修图纸去验房。真正的边界是：今天能看的只有 Maia 200 在 Copilot 生产负载上的表现，以及那条有明确场景的 1.7 倍。

这枚芯片替不替 GPU，问题该反过来问

把整件事收回到一个判断：Maia 200 是微软给自家业务算的一笔能效账，账本写得很细，限定也写得很清楚。它跑在 Teams、Copilot、Cowork 里，跑在 3nm、216GB HBM3e 和 6144 颗集群上，跑在美国、欧洲、澳大利亚的数据中心里。至于它能不能替 GPU，也许该换个问法：你的负载，像不像 Copilot 那一段？如果答案是不像，那 1.7 倍就只是别人的厨房故事。如果答案是很像，下一个该问的，是这套厨房接不接外部订单。

常见问题

1.7 倍是对所有 GPU 的通用优势吗？

不是。这个数字有明确场景限定：Microsoft Teams、Copilot、Cowork 的内置功能，对照的是「领先 GPU 基础设施」，措辞是「最高提升 1.7 倍」，属于微软的厂商口径。微软 2026-10-28 财报电话会提的也是 Teams 与 Copilot 的每瓦 token。换成别的负载或别的对照基线，这个倍数不成立，不能当通用基准使用。

Maia 200 现在能采购到吗？

公开信息里没有对外销售安排、定价或一般可用的采购入口。已核验的是：Maia 200 投入规模化生产，已部署美国、欧洲、澳大利亚，服务 Copilot 生产负载，并逐步支持 GitHub Copilot 与 Microsoft Foundry。微软称 2027 年 Azure Maia 系统会扩到多吉瓦级，那属于计划。生产部署和可对外下单是两件事，别把前者读成后者。

Maia 300 的 40% 提升能算进今天的选型吗？

不能。Maia 300 计划 2027 年投产，采用台积电 N2P 加 chiplet，每瓦 token 再提升约 40%，这些都是计划而非交付。按官方口径换算，约 40% 是同样一度电从 100 个 token 到 140 个，但目标值要等有实际部署和可比口径时再核。今天能作为依据的，只有 Maia 200 在 Copilot 生产负载上的表现和那条带场景限定的 1.7 倍。
