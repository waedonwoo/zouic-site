开源硬件许可证怎么读：MIT、Apache-2.0、GPL-3.0、CERN OHL、CC BY-SA 一次讲清

开源不等于随便用：先看授权，再动手复刻

  1. 首页
  2. 技术文章
  3. 开源硬件许可证怎么读：MIT、Apache-2.0、GPL-3.0、CERN OHL、CC BY-SA 一次讲清

一、先分清：软件许可证管不了硬件

大多数开源硬件项目其实是两套授权叠加：固件代码用软件许可证（MIT、Apache-2.0、GPL-3.0 等），电路与结构用硬件许可证（CERN OHL、TAPR OHL 等）。只看了仓库里的 LICENSE 就以为整块板子可以自由生产，是最常见的误解。

开源硬件的定义可参考 OSHWA 的 OSHW Definition 1.0：设计文件必须公开、允许修改与派生、允许制造和销售，且不得歧视任何人与任何用途。注意其中一条常被忽略——开源硬件并不要求免费，按设计制造出来的产品可以正常售卖。

二、三种常见软件许可证

许可证性质你的义务对复刻售卖的影响
MIT宽松型（permissive）保留版权声明与许可声明影响最小，可闭源派生
Apache-2.0宽松型 + 专利授权保留声明、变更说明、NOTICE 文件，并附带专利授权可闭源派生，专利条款更明确
GPL-3.0强著佐权（copyleft）分发衍生作品时必须以同一许可证提供源代码改了固件并分发，就要开源你的改动

完整条文以 Open Source Initiative 及各许可证官方文本为准，例如 GPL-3.0 页面。

三、硬件许可证：CERN OHL v2 的三个变体

CERN 为硬件设计的许可证目前是 version 2，并且分成三个变体（据 CERN OHL 官方页）：

变体全称含义
CERN-OHL-Sstrongly reciprocal（强互惠）派生设计必须以同等条件公开
CERN-OHL-Wweakly reciprocal（弱互惠）修改设计文件需公开，范围较 S 窄
CERN-OHL-Ppermissive（宽松）保留署名即可，限制最少

换句话说，看到一个硬件项目标着 CERN-OHL-S 和标 CERN-OHL-P，你能做的事完全不同——先看变体字母，再决定能不能闭源派生。

四、CC BY-SA 能不能用在硬件上？

不少项目把设计文件、文档或图片标成 CC BY-SA。需要知道的是，Creative Commons 官方在 FAQ 里明确表示：不建议把 CC 协议用于软件，也不建议用于硬件（原文：CC 不推荐使用其许可协议的类别只有计算机软件与硬件两类）。CC 协议可以用在软件文档这类内容上，但不适合承载电路与结构设计的授权。

所以，如果一个硬件项目的设计文件只写了 CC BY-SA，说明作者可能没有选用专门的硬件许可证；这种情况下要商用，最好直接联系作者取得书面确认。

五、ZouIC 的标注规则

  • 仓库写明许可证的照录：如 MIT、Apache-2.0、GPL-3.0，直接展示原始值。
  • 原页面没写清的一律不猜：标注“以原页面标注为准”或“以原项目页标注为准”。
  • 报道类条目标注性质：Hackaday 条目标注“报道文章，非代码仓库；授权以原页面标注为准”。
  • 不做任何法律定性：本站提供的是索引与线索，不是授权意见书。

逐条查看：开源项目总库；协议说明汇总见 开源协议 页。

六、复现前的五步自检

  1. 确认仓库里 LICENSE 文件的具体名称与变体（不是“开源”两个字）。
  2. 区分固件与硬件两套授权，分别看。
  3. 检查设计文件是否为可修改的原生格式（如 KiCad 工程），而不是只有 PDF 或 Gerber。
  4. 要商用或量产，回到原页面找作者的商业授权说明，或直接联系。
  5. 没写许可证的项目，默认视为保留所有权利，不要想当然。

本文为通用知识整理，不构成法律意见；具体项目请以原作者公布的许可证全文为准。

常见问题

标 MIT 的硬件项目，我能直接生产来卖吗？
要看设计文件用的是哪套硬件许可证。MIT 通常只覆盖固件代码，电路与结构可能另有约定；OSHWA 的定义允许售卖，但前提是遵守该项目所选的许可证。
项目完全没写许可证怎么办？
默认视为保留所有权利。可以联系作者确认，或在取得书面授权前仅做学习研究用途。
GPL-3.0 的固件，改了之后必须开源吗？
如果你分发了修改后的固件，按 GPL-3.0 需要以同一许可证提供源代码；仅自己使用不分发则触发条件不同，具体见许可证全文。
CERN OHL 的 S / W / P 怎么选？
想让派生设计也必须开源选 S；只要求设计文件层面互惠选 W；希望最少限制选 P。
