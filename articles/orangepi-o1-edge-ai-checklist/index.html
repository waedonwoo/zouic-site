16 TOPS 开发板到手，先验这几项

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

OrangePi O1 的 16 TOPS 是 Sophgo BM1688 上 TPU 的 INT8 厂商峰值算力，不等于实际模型吞吐。厂商规格经 CNX Software 中文站 2026-10-15 等媒体转载。到手先查 Ubuntu 镜像与文档是否可取，再核对精度与模型格式、存储互斥项、散热与供电、网络与摄像头接口，最后用目标模型实测。基准日 2026-11-21。

何事 · What：规格清单

按转载的厂商规格，OrangePi O1 为 90×70mm，主控 Sophgo BM1688，CPU 为 8 核 Arm Cortex-A53 1.65GHz 加 RISC-V C906 1.2GHz。TPU 厂商峰值：INT8 16 TOPS、INT4 32 TOPS、FP16／BF16 4 TFLOPS、FP32 0.5 TFLOPS。内存 8GB 或 16GB LPDDR4／LPDDR4X。存储可选 16／32／64／128GB eMMC 或 128／256Mbit SPI Flash，二者互斥。接口有 M.2 M-Key（PCIe 3.0 NVMe）、独立 SATA 3.0、microSD、双千兆网口（YT8531C PHY）、Wi-Fi 6E／蓝牙 5.3、M.2 B-Key（可选 4G／5G）、HDMI 2.0 4K60、MIPI DSI 与 2 路 MIPI CSI、USB3.0／USB2.0 各 2 个、26 针 GPIO。供电 USB-C 20V／3.25A，12V 风扇接口，76g，支持 Ubuntu 22.04。厂商称可本地部署 Gemma-2B 等模型，属厂商口径。

何因 · Why：峰值不等于吞吐

16 TOPS 对应 INT8 档，INT4 的 32 TOPS、FP16／BF16 的 4 TFLOPS、FP32 的 0.5 TFLOPS 是同一 TPU 在别精度下的峰值。峰值是理论上限，实际吞吐还受模型格式、内存带宽、散热和推理框架影响，规格清单未给出这些条件。把 16 TOPS 读成模型的每秒推理次数，是把理论上限当实测结果。厂商列出的可部署模型无吞吐与测试条件，不能替代实测。

何人 · Who：按用途查项

跑本地模型的人先查 Ubuntu 22.04 镜像和官方文档是否可取，再确认模型精度与格式能否被框架读取。管存储的人先确认装 eMMC 还是 SPI Flash，两者互斥，选错则启动方案不成立。管散热供电的人对照 12V 风扇接口和 USB-C 20V／3.25A 条件。接外设的人看双千兆网口、Wi-Fi 6E／蓝牙 5.3、4G／5G 选项和 2 路 MIPI CSI。用途不同，关注项不同。

何时 · When：转载、上架与核查

厂商规格经 CNX Software 中文站 2026-10-15 等转载，这是规格来源的时间点。该站提到产品页称已有 Ubuntu 镜像，但当时 Google Drive 目录为空、官方文档尚未推出，只作方向性线索。第三方零售上架日期 2026-11-01 与渠道价格同样是方向性线索，不进结论。基准日 2026-11-21 是本站核查时点，既非发布日也非上架日。

何地 · Where：规格、产品页与渠道

尺寸、主控、CPU、TPU 峰值、内存、存储与接口落在厂商规格表，经媒体转载，可逐项核对。Ubuntu 镜像的说法落在产品页，CNX Software 中文站指出当时 Google Drive 目录为空、官方文档尚未推出，属待确认状态，不进结论。上架日期和渠道价格落在第三方渠道，也不进结论。把产品页的一句已有镜像写成镜像已可取，最容易在到手前误导准备。

如何 · How：到手核对顺序

第一步查镜像与文档：确认 Ubuntu 22.04 镜像与官方文档是否可取，取不到记为待确认。第二步核对精度与模型格式：确认目标模型用 INT8、INT4、FP16／BF16 还是 FP32 档，格式能否被框架读取。第三步确认存储互斥：核对装 eMMC（16／32／64／128GB）还是 SPI Flash（128／256Mbit），两者不能同装，启动方案按实际介质定。第四步查散热与供电：对照 12V 风扇接口与 USB-C 20V／3.25A。第五步查接口：核对双千兆网口、Wi-Fi 6E／蓝牙 5.3、4G／5G 与 2 路 MIPI CSI。第六步用目标模型实测：记下实际吞吐，与 16 TOPS 峰值分开保存。

边界：峰值与镜像状态都不写死

几处边界要守住。16 TOPS 是 INT8 厂商峰值，INT4 的 32 TOPS、FP16／BF16 的 4 TFLOPS、FP32 的 0.5 TFLOPS 同理，都是理论上限，不等于实测吞吐。厂商列出的可部署模型无吞吐与测试条件，不能写成已验证性能。产品页称已有 Ubuntu 镜像，但 Google Drive 目录为空、官方文档尚未推出，来自 CNX Software 中文站的方向性线索，只作待确认项。零售上架日期 2026-11-01 与渠道价格不进结论。

结论：先验可取性，再谈峰值

OrangePi O1 的规格清单很完整，从 BM1688、8 核 Cortex-A53 加 RISC-V C906，到 INT8 16 TOPS 的 TPU 峰值、8GB／16GB 内存和各类接口，均经媒体转载。但 16 TOPS 是 INT8 厂商峰值，并非实测吞吐，可部署模型也只是厂商口径。到手后先查镜像与文档，再核对精度、格式、存储互斥和接口，最后用目标模型实测，把吞吐与峰值分开记录。

常见问题

16 TOPS 能直接当实测性能吗？

不能。16 TOPS 是 INT8 厂商峰值，INT4 为 32 TOPS、FP16／BF16 为 4 TFLOPS、FP32 为 0.5 TFLOPS，都是理论上限。实际吞吐受精度、格式、内存、散热和框架影响，必须实测。

eMMC 与 SPI Flash 能同时装吗？

不能。厂商规格写明两者互斥：可选 16／32／64／128GB eMMC 或 128／256Mbit SPI Flash，二选一。启动方案按板上实际介质定，M.2 M-Key 的 PCIe 3.0 NVMe、独立 SATA 3.0 与 microSD 是另外的通道，不替代此选择。

镜像与文档缺失该怎么处理？

CNX Software 中文站指出产品页称已有 Ubuntu 镜像，但当时 Google Drive 目录为空、官方文档尚未推出，只作方向性线索，不进结论。到手前把可取状态记为待确认，向厂商或渠道核实；取不到就不要按已可用来规划。
