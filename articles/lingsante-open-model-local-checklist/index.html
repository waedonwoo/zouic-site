124B模型塞进笔记本，先别急着看体检报告

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

124B 参数能塞进笔记本电脑，一份能让它进临床的监管文件却塞不进去。据媒体报道，11 月 23 日，蚂蚁百灵医疗健康大模型家族在广州举行的 2026 蚂蚁阿福医疗健康生态大会上集中发布，两款核心模型同步开源。截至 2026-11-24，官网与报道能看到的参数很漂亮，能回答的问题却很有限。先把一句话写在纸上：能跑起来，和能拿来用，是两件事。

谁跑得动，谁买单：先分清两款模型

LingSante-3.1-air-VL 总参数 124B、每 token 激活 5.5B，原生多模态，能读文字、图片和视频，公司称可部署在笔记本电脑等本地设备上，面向医疗影像报告、皮肤疾病识别和医疗报告解读。124B 听着吓人，真正每次要点亮的只有 5.5B，相当于一个大厨房里只开一只小灶，灶台总面积写着 124B，厨师实际只守着 5.5B 那口锅。另一款 LingSante-3.1-flash 是 560B 总参数、每 token 约激活 25B、最长 1M token 上下文，面向专业医疗机构的复杂医学推理，支持多轮资料检索、医学证据核验和工具调用。它更像一次摆开的宴席，后厨 560B 的家底全要上，1M token 上下文能摊开一大摞病历。谁跑得动、谁买单，答案就藏在这组对照里：小灶你在笔记本上自己烧，宴席得有人替你付账。

下载之前，先把许可证和上下文口径抄下来

据媒体报道，权重通过 Hugging Face 与 ModelScope 开放，许可证为 MIT。MIT 三个字值钱在可以不改主意地拿去改，部署前先把许可证原文、仓库地址和权重版本抄进一张表，别只存一个链接。上下文口径要单独记一笔：据媒体转述，air-VL 的上下文为 256K token，这是转述口径，不是官方公布的数字，抄的时候在后面标上来源。公司称阿福 App 有 1.5 亿用户、每天线上问诊近 2000 万次，这两个数出自公司口径，说的是 App 的规模，抵不上你本地那份模型的准确率。听诊器挂在脖子上和听诊器能听出病，是两回事；把许可、版本、上下文口径分别记清楚，才谈得上后面的复核。

本地部署从最小的一步开始

部署别一上来就想全功能。第一步只做一件事：让 air-VL 在本地把一段文字读懂，确认能加载、能返回，把这一步的耗时和报错记下来。第二步喂一张图片，看它能不能说出影像报告里写了什么；第三步再视频。每一步都单独记录，别把三步揉成一次成功就收工。公司称支持在本地设备部署，落到你手里就是这句承诺要在你自己的机器上跑一遍。听诊器与病历柜：病历柜塞得满满当当，不代表听诊器已经听过每一次心跳，先确认设备本身能用，再往里堆资料。笔记本和医疗机构两条路线在这里分岔，谁在笔记本上跑、谁把 flash 交给机构，部署前就得写死，别边跑边改主意。

每次推理都留下能回看的证据

LingSante-3.1-flash 支持多轮资料检索、医学证据核验与工具调用，这三件事每做一次都要留痕。把输入、检索到的资料、工具调用记录和输出一起存下来，像医院把每张片子连同报告一起归档，日后才回看得清。air-VL 做皮肤疾病识别或医疗报告解读时也一样，输入的那张图、那句提问要和输出一起保存，别只留一个漂亮的结论。证据留存的意义在复核那天才显现：没有原始输入，再好的模型也没法解释它当时看到了什么。官方公布的东西你可以引用，本地跑出来的东西必须自己存。这一步偷懒，后面所有复核都悬在半空。

跑通不等于能用，复核要问三句话

据 HealthTechAsia 报道，公司尚未提供独立临床验证、监管批准或模型用于临床决策的具体条件细节。复核就要盯这三处。第一句：这个输出有没有独立临床验证撑着？第二句：相应的监管批准在不在？第三句：模型用于临床决策的具体条件写没写清楚？三个问题都指向同一件事，体检报告与说明书的区别。体检报告给你一串数字，说明书告诉你这药在什么条件下能吃、什么人不能吃；124B 能塞进笔记本是一份漂亮的体检报告，临床决策的条件说明书眼下还没翻到。跑通只是第一步，复核是把跑通的结果往这三句话上挨个对。态度得摆明：没有条件细节，就别替它补一个。

发现它识别错了，先别再喂第二张图

air-VL 在皮肤疾病识别上给出一次看着不对的结果，先做的动作应当是把这次输入和输出冻结起来，别急着再喂一张图碰运气。据公司口径，LingSante MedGuard 用来识别医疗安全、合规与伦理风险，异常出现时它应当被叫醒，而不是被跳过。把异常分成两类记：一类是模型说错了，一类是模型不该说却说了。前一类留给复核，后一类立刻停手。厨房里灶台着火，先关火再讨论菜谱；异常处理也一样，先停掉那条推理链，再回头查是哪个环节出了问题。别把一次异常当成偶发，连着三次记下来，你手上才有能判断的资料。

有些事它今天不该做

据发布口径，LingSante Pulse 支持 150 余项疾病未来六年的风险预测，LingSante Live 支持实时音视频交互，能识别药品、估测呼吸频次和心率，并接入阿福 App 的视频问诊。能力清单越长，越要划出它今天不该碰的线。风险预测说的是概率，不是诊断书；估测呼吸频次和心率说的是参考，不是监护仪读数。这两句话得写进边界那张纸。说明书没写的适应症，别自己替它补；监管没批的用途，别拿公司口径当通行证。边界清楚了，你才知道这台机器该放在工作台的哪个位置。

最后那道关，写在纸上再去用

回到开头那句反常：124B 塞得进笔记本，监管文件塞不进去。截至 2026-11-24，公开口径给足了参数和许可证，没给独立临床验证、监管批准和临床决策的具体条件。你要过的关只有三道：许可和口径抄清了没有，每次推理的证据存下来没有，复核的三句话问出口没有。三道都过了，这台本地模型才算从体检报告变成你能用的说明书；少一道，它就还只是笔记本里一个跑得动的数字。答案不在参数表上，在你那张写满记录的纸上。

常见问题

两款 LingSante 模型该怎么选？

看场景。据公司口径，LingSante-3.1-air-VL 总参数 124B、每 token 激活 5.5B、原生多模态，面向医疗影像报告、皮肤疾病识别和医疗报告解读，公司称可在笔记本等本地设备部署，据媒体转述上下文为 256K token。LingSante-3.1-flash 总参数 560B、每 token 约激活 25B、最长 1M token 上下文，面向专业医疗机构的复杂医学推理，支持多轮资料检索、医学证据核验与工具调用。前者适合你在本地先试，后者更依赖机构侧的算力和预算。

256K 上下文能直接当官方数字用吗？

要标来源。据媒体转述，air-VL 的上下文为 256K token，这是转述口径，不是官方公布的数字，写进准备表时应在后面注明来自媒体报道。据媒体报道，权重经 Hugging Face 与 ModelScope 开放，许可证为 MIT，这一条也要连同仓库地址和权重版本一起记下。公司口径的数字与媒体转述的数字分栏记，别混成一行。

本地跑通了，能不能用于临床决策？

先别急。据 HealthTechAsia 报道，公司尚未提供独立临床验证、监管批准或模型用于临床决策的具体条件细节。跑通只说明模型能在你的机器上加载并返回结果，不等于它拿到了临床用途的通行证。把每次推理的输入、检索资料、工具调用和输出都存下来，再按有没有独立验证、有没有监管批准、条件细节写没写清楚三句话逐项核对。
