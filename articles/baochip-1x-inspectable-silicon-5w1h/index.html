能自己验的芯片：Baochip-1x 走到了哪一步

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

结论先说：Baochip-1x 把开源硬件的信任边界，从「源码可读」往前推到「硅片可验」，但官方措辞是 mostly-open，不是 fully open。能核对的是计算逻辑 RTL、引导程序与操作系统，以及封装设计支持的红外原位检查；仍然只能信任代工事实的，是台积电 22nm 工艺底层的物理实现。把这两层分开看，才不会把一次有意思的工程尝试，误读成一条已经成熟的采购路径。这就像买一台可以拆开看主板的机器：螺丝在，图纸在，不等于每个焊点都能自己复测。

一颗把检查口留在封装上的微控制器

按 Baochip 官网与 Crowd Supply 项目更新，Baochip-1x 是一颗基于台积电 22nm 工艺的微控制器：350MHz 的 Vexriscv CPU 带 MMU（内存管理单元，让虚拟内存可以在小型嵌入式设备上成立），旁边是一组被称为 BIO 的四核 700MHz PicoRV I/O 协处理器，片上带 4MiB RRAM 与 2MiB RAM，并集成 TRNG（真随机数发生器）、AES 与若干哈希单元。它面向的是 Xous——一个用 Rust 写的微内核操作系统。最关键的设计不只是参数，而是封装专门为 IRIS（红外原位检查）做了准备：用 noninvasive 的红外方式看硅上晶体管阵列的排布，对照公开设计确认拿到的是不是该拿的芯片。一个可反驳的主张是：把「开源芯片」直接等同于「所有层都可审计」，这在 Baochip-1x 上并不成立，官方自己写的是 mostly-open。

供应链信任不能只靠一纸承诺

这类芯片出现的理由，不是把性能做到多高，而是把「你拿到的是不是你以为的那颗」变成一个可现场核对的问题。bunnie 在官方博客里讲得很直白：买安全芯片的常常是银行和政府，技术评估外包，管理者关心的是风险；源码在这种场景里往往没人看。Baochip 的做法是把可核对性前置——引导程序开源且无 NDA（保密协议），大部分计算逻辑源码开源且无 NDA，封装支持红外检查。可反驳的主张是：只要厂商承诺「开源」就足够了。事实恰恰相反，如果检查手段不在封装层留出来，所谓审计只能停在文档层面，供应链环节的替换无从发现。这里补上的正是那道从文档到实物的闸门。

适合谁，以及谁该先等等

官方定位与生态现状决定了适配人群。Baochip 官网写明它是 Rust-first 生态，Xous 是参考操作系统， BIO 协议模拟器和基于开源 RTL 的 BIO-sim 已经可用；也就是说，愿意在 Rust 微内核上写驱动、并且需要可审视硬件的研究者、嵌入式安全团队与高保障设备开发者，是最直接的对口读者。反过来，指望拿来直接跑 Linux 的团队要先确认软件栈现状——MMU 让 Linux 在技术上可能，但官方支持重心在 Xous，不能把可能当成已有。可反驳的主张是：把「有 MMU」写成「支持 Linux」，这是把硬件能力当成软件交付，差了一整个移植工程。对以成熟工具链和长期供货为第一优先的产线采购，现阶段更适合观察，而不是替换。

量产时间要按官方口径分层记

时间线上有两处必须分清。Crowd Supply 的项目更新写的是一次众筹，限量 3500 块 Dabao 评估板，起价 9.50 美元，预计 6 月交付，并附了晶圆良率达到假设的前提；Baochip 官网给出的则是更长期的口径：芯片量产从 2026 年第二季度开始，从空白晶圆到卷带封装需要约 20 周，因此通用供货安排在 2026 年第四季度。前者是众筹批次的预计交付，后者是公司层面的通用供货安排，不是同一个节点。可反驳的主张是把两者取平均、或者只留一个「2026 年」的模糊说法。正确做法是并列写下、标明各自出处与前提，并注明基准日 2026-11-19；良率假设一旦不成立，众筹交付时间就会滑动。

可核对的边界画在哪一层

官网把边界说得不含糊：芯片源代码、核心与外设参考指南、硬件参考文档、Xous 操作系统与板级支持包都在公开仓库里；与台积电 22nm 工艺相关的底层物理设计仍是专有的。也就是说，可核对性落在 RTL 与版图可红外观察这一层，不落在工艺文件这一层。交付路径也是公开的：Crossbar 负责流片并在台积电制造晶圆，Baochip 从 Crossbar 买入封装测试好的芯片；用户也可以直接从 Crossbar 买同款芯片，但那批不带 Baochip 预装软件，应用与软件支持也归 Crossbar。可反驳的主张是「同一颗芯片软件支持必然一样」——芯片相同，交付内容不同，支持责任方就不同。这条边界在采购单上必须写清楚。

评估这类芯片按四步走

第一步，先把需求翻译成可核对项：是否需要虚拟内存，是否需要 TRNG、AES 与哈希这些片上原语，是否真的需要红外检查能力，把「想要开源」拆成具体能力。第二步，确认软件栈能不能落在 Xous 上，或者团队有没有能力移植其他基于 Rust 的微内核；官网明确 BIO 有模拟器和加载工具，可以先在模拟环境里跑通再上板。第三步，确认供应路径：走 Crowd Supply 的 Dabao 评估板，还是走 Crossbar 的直接渠道，两条路的软件预装与支持责任不同。第四步，如果需要审计，把红外检查设备与判读工时算进预算，并事先约定「核对不一致时怎么处置」。可反驳的主张是：把第四步当成可选附加项——如果买它的理由就是可审视，那么不具备判读能力的审视不算审视。

这款芯片不解决什么

它不解决通用算力问题，也不解决成熟软件生态问题。350MHz 的主核与 700MHz 的 I/O 协处理器组，定位在微控制器区间，不是拿来处理大模型或通用计算的；软件重心在 Xous，不是在主流 Linux 发行版。它也不替代形式化验证：能看见晶体管排布，回答的是「这颗是不是按公开设计做出来的」，不是「这段逻辑有没有形式化正确」。可反驳的主张是：把可红外检查说成「彻底排除后门」。这是两种不同强度的断言，前者是证据手段，后者是结论，中间还隔着判读流程与覆盖度。另外，官网提到公司目前只有一个人、自筹资金、没有投资人，这不是缺点，但意味着产能与支持的节奏要按小团队预期来排。

它的价值是给信任加了一层可核对的证据

把 Baochip-1x 放进产业视角，它的意义不在于性能坐标，而在于把「可审视」从口号变成封装层面的设计选择。对于需要证明供应链完整性、又无法自己流片的团队，这是一条值得跟踪的路径；对于只想买一块便宜开发板跑现成系统的读者，现在不是最省事的时点。一个可反驳的主张是：开源芯片只要把 RTL 放出来就完成了使命。Baochip 的做法说明，真正卡住高保障场景的往往不是源码，而是拿到手的实物能不能核对。这个判断不依赖它最终出货多少，也不依赖哪家大厂跟进。

常见问题

IRIS 检查到底能证明什么？

它回答的是「这颗芯片的晶体管排布是否与公开设计一致」，是一种非破坏性的实物核对手段，前提是封装为它留了条件、判读方有设备和能力。它不回答逻辑是否正确，也不替代形式化验证。

为什么官方写 mostly-open，而不是 fully open？

因为计算逻辑 RTL、引导程序与软件栈公开且无 NDA，但与台积电 22nm 工艺相关的底层物理设计仍是专有的。把它说成完全开源，会高估可核对范围，尤其在审计场景里这个差别很关键。

现在适合把它用在量产项目里吗？

要看目标。需要可审视硬件做研究或高保障验证的团队，可以从 Dabao 评估板起步；要求成熟工具链、长期供货与现成 Linux 支持的产线，更适合先观察软件栈和供货节奏，不要按通用微控制器来排期。
