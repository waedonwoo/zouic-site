MCP 一次补八个洞，先做这四步

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

同一周里，三件事指向同一个动作：把手里的钥匙重新数一遍。MCP 服务器 v2.6.0 在 11 月 27 日一口气修补八个漏洞；微软 Agent Framework 的 Python 包 1.26.1 和 1.26.2 被未授权上传至 PyPI，内含窃密代码，仓库临时下线；一家研究机构测出工具投毒的攻击成功率是 22.9%。三件事不是一条线，但它们都要求你回答同一个问题：这把钥匙到底能开几扇门。

八个洞分别漏在哪？

v2.6.0 修的八个漏洞里，最值得单独拎出来的是三类。mcp-server-git 允许 Git LFS 执行恶意程序，等于把一次拉取变成了执行；path 扩展会泄漏环境变量，环境变量里常常躺着密钥；远程名称欺骗能泄漏认证凭据。Windows 版 filesystem 服务器也在修复之列。这三类有个共同点：它们都不是让模型说错话，而是让工具拿到本不该拿到的东西。把 MCP 只当成一个协议层的问题，会漏掉这一半。

为什么投毒包比漏洞更难防

微软那两个被投毒的 Python 包，坏处写在安装环节：恶意代码在 Python 启动时就执行，与你是否 import 它无关。这意味着只审查自己代码里引了什么，挡不住它。仓库已经临时下线，还没安装的人可以先锁定 1.26.0。这类供应链投毒和 MCP 漏洞的区别在于，漏洞有版本号可对，投毒在你装上的那一刻就已经发生了。数钥匙的动作，因此要往前挪到安装之前。

22.9% 是什么口径？

Dynatrace 的跨框架研究给出一个刺眼的数字：MCP 工具投毒的总体攻击成功率是 22.9%，其中 12.1% 真正完成了凭证外带。这两个数不能混着读：22.9% 说的是攻击有机会得手的比例，12.1% 说的是真的把凭据带出去的比例。后者才是损失发生的那一条线。还有一个画面感更强的对照：AI 攻击框架 Cairn 只用 11 分钟就挖出医疗影像软件 MONAI Label 的零日漏洞。找漏洞这件事，从数周压到了分钟级。截至 2026-11-28，能核对的是这些机构公布的研究结果，它们不是理论推演，而是带真实工具执行的测量。

第一步：先升级，再谈别的

用 MCP 搭工具链的团队，第一件事是把所有服务端和客户端升到 v2.6.0，尤其是启用了 git 和 filesystem 服务的实例。升级之前先列清单：哪些服务是自己部署的，哪些是随第三方镜像带进来的，哪些只在开发机上跑过。第三方镜像最容易被遗忘，它把旧版本封在里面的时间，往往比你想象的久。升级顺序也有讲究，先处理能接触到生产凭据的节点，再处理开发机。钥匙要先从最值钱的门上换起。

第二步：把凭据从环境变量里拎出来

path 扩展泄漏环境变量这个漏洞提醒了一件事：很多人把密钥直接放在环境变量里，图的是方便。一旦有工具能读到进程环境，这些密钥就跟着走了。更稳的做法是把凭据交给专门的密钥管理服务，工具运行时按最小权限临时取用，用完即弃。至少要给环境变量分个级，哪些是普通配置，哪些是真正的凭据，后者不进普通工具能读的范围。把钥匙串拆开挂，比把所有钥匙放在一个环上安全。

第三步：给工具划权限边界

远程名称欺骗能泄漏认证凭据，说明名字本身就是攻击面。一个叫 search 的工具和一个叫 searcn 的工具，在模型眼里差别可能没那么大。缓解办法是给工具加稳定的来源标识，聚合多个服务器时不要只靠短名字区分，同时把每个工具能做的事项收到它真正需要的范围。用 MCP 暴露内容库或组件库的团队，只读要在服务端强制，不能只在描述里写一句只读。描述和实现不一致，恰恰是 scanners 只看代码时看不见的那种问题。

第四步：盯住版本变化，不是盯住一次扫描

装之前扫一遍不等于一劳永逸，工具描述和后端行为都可能随版本更新而变。OWASP 的 MCP 安全备忘单明确建议在批准后继续监控描述与 schema 的变化。防御侧也有新东西：思科与 OpenAI 推出 Shirudo，用 eBPF 加智能体的方式在不重启的情况下拦截利用；Google 上线语义治理政策；Anthropic 推 Siren。这些工具能补位，但替代不了你自己的版本台账。每次更新都记一行，描述变了没有、权限多了没有、行为偏了没有。

钥匙数完了，门还没关

把四步做完，你能拿到的只是一个更清楚的状态：哪些工具在用、各自能碰什么、版本停在何处、凭据放在哪里。这不能保证不出事，但能让出事时的排查时间从几天缩到几小时。MCP 的设计目标是互操作，不是安全边界，这一点在协议里写得明明白白。给智能体配工具的团队，得自己把边界画上。八个洞补完了，下一批洞还会来；能留下来的，是这套数钥匙的习惯。

常见问题

MCP v2.6.0 修了哪些值得注意的漏洞？

11 月 27 日发布的 v2.6.0 修补八个漏洞，其中 mcp-server-git 允许 Git LFS 执行恶意程序、path 扩展泄漏环境变量、远程名称欺骗泄漏认证凭据较为关键，Windows 版 filesystem 服务器也在修复之列。使用相关服务的团队应尽快升级。

微软 Agent Framework 的投毒包为什么要单独处理？

1.26.1 和 1.26.2 被未授权上传至 PyPI，内含窃密代码，仓库已临时下线。恶意代码在 Python 启动时即执行，与是否 import 无关，因此仅审查自己代码的引用挡不住；尚未安装者建议先锁定 1.26.0，并在安装前核对包来源。

22.9% 和 12.1% 分别代表什么？

Dynatrace 跨框架研究显示，MCP 工具投毒的总体攻击成功率为 22.9%，其中 12.1% 真正完成凭证外带。前者是攻击得手的比例，后者是实际造成凭据泄漏的比例，两者口径不同，不能互相替代。
