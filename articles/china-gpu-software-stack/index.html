国产算力的分水岭不是峰值算力，是「迁移要花多少工时」

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026-10-27

2026 年再拿 FP16 算力表比较国产卡，已经问错了问题。客户真正要估的是另一笔账：把现有的训练与推理代码搬过去，需要几个工程师、几个月、以及多少性能损耗。参数表上赢，交付现场输在算子上，是这轮国产替代最常见的失败方式。

兼容率：四家四条路

软件栈公开口径路径代价
海光 DTKCUDA 代码兼容超 95%、算子覆盖超 99%、适配 400+ 模型深度兼容 ROCm / CUDA 双生态底层指令集源自授权，自研比例较低
摩尔线程 MUSA对标 CUDA 12.8、3194 个算子全量、兼容接口 761全栈兼容 + 进开源主线性能与生态仍在追赶
沐曦 MXMACA4490 个 CUDA 项目测试中 4173 个可直接适配（92.94%），260 个需微调开源 Upstream First，与 vLLM 官方合作驱动与 runtime 仍闭源
华为 CANN2025 年 8 月全面开源；兼容约 80% CUDA API、85% 算子自动转换全栈自研 + 指令翻译性能损耗约 15-20%，算子覆盖约 2000 对 CUDA 10000+

这些都是厂商自测或第三方测评报告汇总的口径，不是独立审计。有个事实必须明说：截至 2026 年中，没有任何一家国产栈公布过独立第三方的大规模训练迁移评测。兼容率数字主要来自厂商自测与社区个案，「能跑通多少算子」与「千卡万卡连续生产稳不稳」是两件事。

阵营里最实在的进展，是进主线

比起兼容率，更值得看的是有没有被开源社区接纳。摩尔线程的 TileLang-MUSA 已进入 TileLang 官方主线，能对 DeepSeek-V4 的 TileKernels 算子库做 Day-0 支持；SGLang 主线原生支持、vLLM 官方后端也已落地，S5000 基于 MUSA + SGLang 完成 DeepSeek-V4 全链路验证。沐曦走 Upstream First，PyTorch 算子覆盖与 vLLM 官方合作是它的差异化。海光牵头 HSL 开放互联总线，寒武纪、沐曦、摩尔线程都加入——这是国产阵营少见的、试图在互联层先统一的动作。

差距也藏在同一张表里：vLLM 已在沐曦、昇腾、海光适配，SGLang 在昇腾与海光适配、沐曦适配中，而 TensorRT-LLM 在三家国产平台都不支持。MoE 模型最吃紧的 all-to-all 通信，在国产 GPU 上的性能约为国际旗舰的 50-65%；NVLink 900GB/s 级的互联带宽短期内追不上。评测报告给出的迁移成本更直接：一个中等规模训练项目，CANN 路线估算需要 6-18 个月与 50-200 万元额外工程投入。

兼容是入口，不是终点

行业里通行的做法，是预留 20-35% 性能余量，用国产方案换采购成本与供应安全。这笔账在推理集群、信创政务、科学计算这类负载相对固定的场景算得过来；在互联网大模型训练这种自定义算子密集、通信库深度依赖的场景，重写与调优成本会吞掉硬件价差。

还有一个更长期的问题：兼容模式能快速导入存量应用，却可能让平台停留在「生态附庸」的位置——一旦上游在兼容性上设新壁垒，依附式发展就要被动重来。这也是为什么「进主线」比「兼容率 99%」更有战略价值：前者是在定义规则，后者是在追赶规则。

总结

国产 GPU 的竞争已经从芯片参数转到软件工程：算子覆盖、通信库成熟度、连续生产稳定性、以及工程师重新培训的时间。对采购方，建议把验收指标从「峰值算力」换成三项可测的东西——自有模型端到端跑通所需人天、目标并发下的 P99 延迟、以及千卡连续运行 72 小时的故障率。这三个数字，比任何兼容率都诚实。

常见问题

「CUDA 兼容 95%」能直接理解为代码不用改吗？

不能。这类数字多为厂商自测或特定项目集的通过率，实际迁移仍可能涉及自定义算子重写、通信库替换与性能调优；截至 2026 年中尚无独立第三方的大规模训练迁移评测。

国产卡现在能跑主流推理框架吗？

vLLM 已在沐曦、昇腾、海光适配，SGLang 在昇腾与海光已适配、沐曦适配中；TensorRT-LLM 在这三家国产平台上均不支持，选型前需确认框架版本。

迁移国产平台通常要留多少余量？

行业常见做法是预留 20-35% 性能余量以换取成本与供应安全；中等规模训练项目的迁移周期有测评报告估算为 6-18 个月，并需额外工程投入。
