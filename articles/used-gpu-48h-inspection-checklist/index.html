二手 H100 验卡：把「能不能用」变成一张可复核的清单

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

验卡最容易走偏的一步，是把它做成跑分。跑分只说明这一刻能跑，说明不了这张卡经历过什么，更说明不了三个月后还能不能跑。真正影响成交价的，是买方能不能把「经历过什么」自己复核一遍。

价差来自不确定性，不是来自性能

Introl 2025Q1 的残值报告追踪了 1534 张数据中心 GPU，其中 H100 80GB 的二手均价仍在新卡发售价约 70% 的水平。报告同时提醒：这些卡没有官方保修、故障率在攀升。残值高不等于风险低，恰恰是因为风险没人定价，价格才停在模糊地带。

ITAD 商家自述的口径是，做过专业清洁、测试与包装的翻新分级货，比 as-is 出货多卖 15%–20%。这个幅度来自商家自述，不是第三方实测，写进模型前要自己验；但方向很清楚：多出来的钱买的是「不确定性被标价」，不是卡变快了。

一张能交付的清单有哪些行

NVIDIA 的 Dynamic Page Retirement 文档写得很具体：驱动会把出错的显存页记进 InfoROM，并有 64 页的上限。这个计数是卡的里程表，清不掉也改不了，比任何跑分都诚实。下面这些行全部绑定设备序列号，缺一行，报告就不能叫可复核。

  • 身份与固件：序列号、SKU、VBIOS / 驱动 / DCGM 版本，先固定现场，避免换机后数据对不上。
  • 历史计数：nvidia-smi -q -d ECC,PAGE_RETIREMENT,REMAPPED_ROWS 取 volatile 与 aggregate 两套计数，以及 row remapping 余量。
  • 主动诊断：dcgmi diag -r 3 -j 起步（官方口径约 15 分钟），高价值 SXM 库存补 L4（Dell 文档约 90 分钟），保存逐测试状态 JSON。

链路与满载，是两张最容易漏的表

SXM 卡还要跑 nvidia-smi nvlink -s 与 -e 看链路状态和错误计数；PCIe 卡要在负载下读当前链路代际与宽度，而不是空闲时读，同时记录 Replays Since Reset 并在压测后比对。一张把链路训在 Gen4 x8 的卡，短测会过，带宽却一直少一半。

最后是 48 小时满载 burn-in，同步留下功耗、温度与降频曲线。这里有个很实际的坑：2026 年 10 月的 580.196.07 与 595.112.07 驱动修掉了两个会毁掉验收的现象——nvidia-smi -q 触发的偶发 fallen off bus 误报，以及被 Ctrl-C 中断的 CUDA 任务让利用率一直显示 100%。测试机驱动版本不写进报告，结果就不可比。

结论与边界

把这套流程脚本化，工具全是免费的，壁垒在方法可复现、跨机型基准和判读经验。报告只陈述可复核的历史数据，给「可入生产 / 仅推理 / 仅开发 / 停用」这样的分级结论，绝不预测还能用几年。

还有一条必须写进免责：NVIDIA 明确说明 DCGM 诊断不替代其离线现场诊断，也不决定 RMA 资格，一次失败也可能来自主机、库、散热或供电，而不是卡本身。想做这块业务，先读 错误码判读 与 报告模板，再谈报价。

常见问题

验卡跑一次 3DMark 或推理基准够不够？

不够。基准只反映当下这一刻的状态。决定性信息是 ECC 与 page retirement 历史、row remapping 余量、DCGM 分级诊断结果、链路状态，以及 48 小时满载曲线，这些都需要绑定序列号留存。

page retirement 计数为什么清不掉？

NVIDIA Dynamic Page Retirement 文档说明驱动把失效页记入 InfoROM，并设有 64 页上限。它是设备生命周期记录，不是软件缓存，重装驱动或换机器都不会归零。

检测报告能不能保证这张卡还能用两年？

不能，也不该这么写。报告只陈述可复核的历史数据与当前诊断结果，给分级建议；寿命预测既无数据支撑，也会把检测方拖进担保责任。
