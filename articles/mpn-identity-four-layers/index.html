MPN 不是主键：元器件身份至少要拆成四层

算力行业观察 · 极客微栋 @GeekWaedon

极客微栋 @GeekWaedon · 2026 年 11 月

元器件数据项目的第一个技术决策，往往也是最贵的一个：用什么当唯一键。把厂商标称型号（MPN）直接当主键，看起来天经地义，实际上把「名称」当成了「身份」——同一串字符下，封装、等级、批次和供货形态都可能是不同的东西。

四层身份，加两个外部锚点

可操作的最小模型是四层：品牌 / 制造商 → 系列与器件型号 → 封装与引脚 / 卷带形式（Tray、Tape & Reel 会直接影响贴片与采购最小量）→ 等级与后缀（温度范围、车规、湿度敏感等级、RoHS / 无卤版本）。很多原厂把这些信息压在后缀里，两个字符之差就是能不能上车的区别。

再挂两个外部锚点：丝印号（marking，用于从实物反查型号，尤其是打磨片与翻新件识别），以及生命周期状态（Active / NRND / EOL / Last Time Buy）连同其依据的通知与时间戳。本栏目此前写过替代料最容易漏的四项参数，讲的是「能不能换」；这一篇讲的是更前置的问题——你连在换哪一颗都还没确定。

三类典型翻车

把它们列出来，是为了在库结构设计时对得上：

  • 参数近似、降额不同：常温测试通过，极端温度或长期负载下失效；标称值一样，降额裕度被吃掉。这类差异只存在于等级层，不存在于型号字符串里。
  • 同型号不同封装：原理图符号可以复用，PCB 焊盘、散热路径与钢网开口却完全不同。若库里只存一行，BOM 导入时会把不兼容的封装当成同一颗料合并。
  • 状态没有时间戳：一年前标 Active 的记录，现在可能已发 EOL 通知。没有通知原文与日期，预警功能反而会给出过期的安全感。

数据结构上的四条约束

内部 ID 与对外 MPN 分开，内部 ID 一旦生成不再复用；每条参数断言都带来源、抓取日与手册版本；替代关系不要存成布尔值，要存方向、替代等级与验证条件（例如仅限常温、需重做温循）；生命周期状态单独成表，追加而不覆盖，保留完整变更史。这四条听起来朴素，却直接决定日后能不能对客户说「这个结论可以复核」。

总结

唯一键设计错了，去重会把不同东西合并、替代推荐会把错误放大到整张 BOM。宁可前期多几张表、多几个必填字段，也别在几万条记录之后回头改主键。

常见问题

为什么 MPN 不能直接当数据库主键？

同一型号字符串可能对应不同封装、引脚与卷带形式、温度或车规等级、以及不同批次。替代判断与 PCB 兼容性恰恰依赖这些差异，合并成一行会丢失关键信息。

元器件身份至少要记录哪几层？

品牌 / 制造商、系列与器件型号、封装与供货形态、等级与后缀四层；另加丝印号用于实物反查，以及带时间戳和原始通知依据的生命周期状态。

替代关系为什么不能存成布尔值？

替代通常有方向、等级与验证条件。例如 A 可替 B 仅限常温且需重做温循，写成「可替代 = 是」会把带条件的结论当成无条件结论，在采购环节放大风险。
